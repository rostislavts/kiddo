# AI Lab v2 — работа и проверки

AI Academy е изцяло безплатна. Последователността на уроците остава. Историческата колона `worlds.is_free` е запазена, но не участва в авторизацията. Съществуващата Paddle цена €14.90/месец предоставя AI Lab и **1000 Energy общо за семейството**, с отделна отчетност за всяко дете.

Уроците, тестовете, AI грамотността, теорията за халюцинации/безопасност/prompting и базовите AI мисии са **безплатни завинаги** и са включени и в Premium. Базовите мисии са самостоятелните Detective задачи: предварително подготвени факти, оценка на сървъра, запазени опити и XP, без AI заявка или Energy. Те работят и без абонамент, след прекратяване и при спрян AI доставчик. Допълнителното реално AI обяснение, Featured мисии и Escape Room контекстът запазват Premium проверките. UI и сървърът използват общото правило в `src/lib/lab/access-policy.ts`.

Real prompts, Build-a-Bot, Agents, Image generation, Knowledge/RAG Lab и AI Energy изискват активен семеен или училищен Premium достъп. Таблицата в началната страница, `/pricing` и `/parent/billing` използва един общ компонент и описания от `src/i18n/bg.ts`.

## Настройка на реалния AI

В `.env.local` са подготвени:

```dotenv
AI_PROVIDER=openai
AI_API_KEY=
AI_TEXT_MODEL=gpt-5.4-mini
AI_IMAGE_MODEL=gpt-image-2
AI_LAB_ENABLED=true
```

Попълни само `AI_API_KEY` с ключ от своя OpenAI API проект. Не използвай `NEXT_PUBLIC_` за тайни. Не поставяй ключа в чат, Git или детски проект. Ключът трябва да има достъп до Responses, images/generations и moderations; нужни са активен API billing и разрешение за избраните модели. След промяна рестартирай локалния Next процес. Без ключ няма фиктивни отговори: интерфейсът показва липсващата настройка и не таксува заявки.

Моделите от env са начални стойности при първото зареждане на `ai_settings`. След това `/admin/lab` е източникът за модели, Energy цени и лимити. `AI_LAB_ENABLED=false` е допълнителен авариен стоп извън базата.

Започни с измислени тестови данни. Изискването на OpenAI за обработване на лични данни на деца под 13 години е Zero Data Retention. `store:false` в Responses **не** осигурява ZDR само по себе си. Операторът трябва да уреди правилните настройки и договори с доставчика преди такова използване. Няма качване на детски снимки; Vision използва две локални илюстрации с проверими факти.

Източници: [Responses и Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [насоки за лица под 18](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance), [изображения](https://developers.openai.com/api/docs/guides/image-generation), [moderation](https://developers.openai.com/api/docs/guides/moderation).

## Миграция без нулиране

```bash
npm run db:migrate
npm run db:seed
npm run dev:local
```

`0004_ai_lab_v2.sql` добавя 21 таблици, индекси, ограничения, RLS и compatibility views. `0005_mission_attempt_context.sql` отделя лимитите за опити по мисия/стая/версия и запазва броячите при изтриване на проект. Съществуващите 19 таблици с потребители, прогрес, плащания и XP не се нулират. Командата за миграция инициализира Energy за активните познати абонаменти идемпотентно. Webhook и първото отваряне на Lab използват същия механизъм. Seed добавя липсващите записи и не заменя редактираното през CMS съдържание.

Различните Lab инструменти използват общи `lab_projects`, `ai_runs`, `lab_challenges` и `lab_attempts`. Views като `prompt_runs`, `child_bots`, `agent_runs`, `detective_attempts` и `image_generations` представят имената от PRD, без да дублират еднакви данни. Специализираните карти, разговори, агентски действия, игри и Escape Room стъпки имат собствени таблици. Views са `security_invoker`; публичните Supabase роли нямат директен достъп.

## Изпълнение и Energy

`src/lib/lab/runtime.ts` използва доставчика през `AIProvider`, без vendor-specific business logic. OpenAI адаптерът използва фиксиран API адрес, `store:false`, ограничен размер на отговора, timeout и валидиран JSON. Не извлича и не записва reasoning output. Няма инструменти за интернет, shell, покупки, съобщения или код.

Всички grant, debit, refund и delete операции заключват родителския ред. Една транзакция проверява принадлежност, entitlement, конфигурация, rate/concurrency лимити и баланс и записва резервацията. Мрежовата AI заявка е извън транзакцията. Завършването проверява отново състоянието и версията на проекта. Неуспешен/модериран/невалиден резултат възстановява Energy само веднъж. Изтекли задачи се възстановяват при следващата заявка или от maintenance.

Уникалните request IDs са обвързани с хеш на заявката. Повторена успешна заявка връща запазения резултат без второ таксуване. Повторно използване на ID с различно съдържание се отхвърля. Уникален семеен billing период предотвратява двоен месечен grant; няма rollover по подразбиране. След изтичане не се изпълняват нови Lab задачи, но запазените проекти и учебните награди остават.

`usage_finalized` (amount 0) добавя provider usage към неизменяемия ledger. Цените са администраторска конфигурация; началните оценки са по публикуваните стандартни цени на 26.09.2026. Разходите за различни модели в една задача се отчитат поотделно. Липсваща цена/usage означава неизвестен разход. Оценките не са счетоводна фактура и не включват отстъпки, данъци или неполучена от доставчика информация при грешка. [OpenAI pricing](https://developers.openai.com/api/docs/pricing).

## Инструменти и съдържание

- Prompt Playground: седем блока, действителен prompt, история и сравнение на два опита.
- Prompt Battles: детерминистични проверки за думи, брой елементи, дължина, заглавия и JSON; structured judge само за explicit semantic критерий; лимит за опити и XP веднъж.
- Ботове: конфигурация, видими инструкции, редактиране, ограничена история и optional Knowledge проект.
- Агенти: осем строго валидирани инструмента, лимити за стъпки/извиквания/Energy; три сценария с варианти. Детето вижда действия и резултати.
- Knowledge: редактиране на карти, PostgreSQL full-text retrieval, snapshots на използваните карти.
- Detective: четири режима с предварително зададени проверени факти; динамичното обяснение не променя оценката. Фактите са от [NASA Sun Facts](https://science.nasa.gov/sun/facts/) и [Moon Facts](https://science.nasa.gov/moon/facts/).
- Image Lab: реална генерация, модериране на резултата, частен asset endpoint и сравнение. Мисията възнаграждава prompt критериите; visual feedback е изрично приблизителен.
- Vision: curated SVG/PNG сцени в `public/lab`; реален vision отговор и отделно известни факти.
- Game Master: structured отговор, серверни избори/брояч/край. След започване правилата се променят чрез нов проект.
- Escape Room: пет последователни задачи от общите engines, проверявани на сървъра.
- Creator: четири шаблона, свързани и изпълнени инструменти; за учител/музеен гид ботът трябва да използва свързаните карти.

`/admin/lab` управлява настройки, battle/agent/detective/knowledge/image/escape/creator задачи, Featured мисии с UTC дати, значки и Energy grants. За нова задача от даден вид копирай сходен запис, премахни ID чрез „Копирай като нов“, избери нов slug, редактирай конфигурацията и публикувай. Данните се валидират на сървъра. Започнати Escape Rooms не променят стъпките си; за нов вариант създай нова стая. За нов месечен период създай нов Featured запис. Seed не препубликува стара мисия автоматично.

## Поверителност и съхранение

Родителският преглед и стандартният export показват заглавия, състояние, Energy и обща активност. Не включват raw prompts, bot messages или AI outputs. Детският workspace показва само собствените му проекти и история. Това е семеен акаунт: родителят може изрично да влезе в детския профил през съществуващия избор на профил.

Генерираните JPEG изображения са ограничени по брой/размер и се пазят като private bytes в PostgreSQL за тази бета. Не съществуват публични линкове. `/api/lab/assets/:id` проверява родителската собственост и expiry и изпраща `private, no-store`. Изтриването на проект/профил каскадно изтрива съответните изображения, разговори и записи. Изтриване на дете възстановява висящите резервации и анонимизира неговите ledger записи, за да запази семейния баланс.

Raw историята и изображенията имат начална retention политика 30 дни; проектната конфигурация и учебните награди се пазят до изтриване. Maintenance премахва expired assets и raw history, като пази оценки, counters, XP и отчетността за Energy.

```bash
npm run db:maintenance
```

Vercel cron извиква `/api/maintenance` ежедневно в 03:17 UTC. Задай `CRON_SECRET` в production environment; endpoint-ът изисква съответния Bearer token. Локален секрет вече е генериран в `.env.local`. На локална машина cron не се изпълнява автоматично — използвай командата.

## Проверки

```bash
npm run check
npx playwright install chromium
npm run test:e2e
```

E2E по подразбиране прави изолиран **production build** в `.next-e2e` и стартира Next на 3100, PGlite socket на 54328 и локални Auth/Paddle/OpenAI fixtures на 54329. Provider transport е заменен само в тестовия процес чрез NODE_OPTIONS. Приложението няма тестов auth/billing/AI bypass. За интерактивно дебъгване: `E2E_DEV=true npm run test:e2e`. Може да се използва вече наличен Chrome чрез `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

Автоматизираните сценарии покриват безплатни светове, checkout/webhook entitlement, Energy, prompt сравнение, battle награда, бот, RAG provenance, private assets, vision, игра с презареждане, Creator проект, всички Escape стъпки и CMS публикуване. Unit/integration проверките покриват грешки, refund/replay, concurrency, rate/kill switches, ownership, moderation, tools, исторически записи, изтриване и retention.

След добавяне на ключа `npm run ai:smoke` изпълнява реални text/moderation, structured vision, агент и една image заявка с измислени данни. Изображението се пази само в игнорирана `.test-data/ai-smoke`. За пропускане на image генерацията: `npm run ai:smoke -- --text-only`. Това използва API бюджета на оператора.

Тестовият OpenAI transport не доказва достъп до реалните модели. Преди private beta провери реални text, structured, image и vision заявки с ключа на оператора и отделен тестов родител. За cloud средата са нужни също собствен Supabase SMTP и одобрение на checkout домейна в Paddle Sandbox, както е описано в README.
